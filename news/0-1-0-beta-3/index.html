Assiduous Engine 0.1.0-beta.3

12 November 2026

The third beta of Assiduous Engine is out.

This release is largely the result of testing the sample games on a phone. That testing uncovered a few problems that weren’t limited to mobile. In particular, games could look different in the player than they did in the editor, and startup could be painfully slow. Both are fixed in this release, along with a number of other issues.

If you’re upgrading from 0.1.0-beta.2

  • Root motion: The mode that leaves root motion to the game to apply is now called Manual instead of Script. Scripts referencing it should use RootMotionMode::Manual. Existing saved scenes are unaffected.
  • Networking: The reliable UDP transport’s wire format has changed. Games built with beta.2 cannot communicate with games built with beta.3.
  • GUI: Commands that all handlers pass on are now treated as unhandled. runCommand returns false, and the key continues through normal input handling.
  • Native code: The SDL3 shell has moved to Shell.SDL3 (module foundation.shell.sdl3, target Foundation::Shell.SDL3). The Dear ImGui plugin now draws itself as a screen overlay, so applications with a render subsystem no longer need to call ImguiSubsystem::Render.

Fixes

  • Post-processing with MSAA: With MSAA enabled, the player was replacing a scene’s post-processing settings (auto exposure, ambient occlusion, reflections, TAA) with engine defaults. This made games look darker and flatter than they did in the editor. All the sample games had 4x MSAA enabled, so they were affected. The player now respects the scene’s settings, and play-in-editor uses the project’s MSAA setting as well.
  • Startup performance: Sky lighting and reflection probes were being baked repeatedly during a scene’s first 20 frames. On a phone, this kept games running at around 4 FPS for their first five seconds. Both now bake only once.
  • Vulkan: Fixed a descriptor set being freed while still in use by a frame, which could happen when starting a scene with MSAA enabled.
  • Networking: Fixed reliable messages not being resent when their first packet was lost, clients being unable to reconnect from the same address, and sequenced messages arriving out of order.
  • Editor: Fixed preset settings not appearing in the Export dialog and incomplete project thumbnails when opening a project before its first cook.

What’s new

  • Back key: The keyboard or browser Back key can now be bound like any other input. In menus, it works like Escape.
  • Export: Export presets can now include additional files from the project, which are packaged alongside the game. Tools.Export --content-only stages game content without a player, while --platform exports a preset for another platform.
  • Mobile groundwork: The player can now rotate its output for displays with a different orientation, respect screen safe areas, and pause and save when the app moves to the background.
  • 4x MSAA by default: New projects now start with 4x MSAA enabled, as do the sample games.
  • Sample games: Lamplight and Masquerade now use FXAA instead of TAA while TAA continues to receive further work.

The full list of changes is in the changelog.

Get it

Download the latest version for your platform, or visit the 0.1.0-beta.3 release on GitHub.

The editor’s project manager downloads the sample games for its version, and you can try this release in the browser through the demos.

If you run into any issues, open a GitHub issue and I’ll take a look.

AssiduousEngine is a game engine in C++23, with its editor, asset pipeline and tools.
