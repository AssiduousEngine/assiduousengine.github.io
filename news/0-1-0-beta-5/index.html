Assiduous Engine 0.1.0-beta.5

22 November 2026

The fifth beta of Assiduous Engine is out.

This release changes quite a bit about how gameplay code is organised. Behaviors now declare their type by deriving from EntityBehavior, SceneBehavior or RunBehavior, rather than relying on reserved class names. You can also write any of these behaviors in C++ as part of a project’s own plugin, without using a scripting language.

There’s also a new sequencer for building cutscenes, a dialogue plugin for writing conversations, and Android export.

If you’re upgrading from 0.1.0-beta.4

Most of the changes are renames, but scripts need a few adjustments before they’ll run.

  • Scripts declare their kind: A behavior now derives from its type: class Coin : EntityBehavior in AngelScript, or Coin = EntityBehavior.class() in Luau. The same applies to SceneBehavior and RunBehavior. The reserved Game and Level class names are gone, so you can name your classes whatever you like. A class that doesn’t derive from one of the behavior types will be rejected when assigned as a behavior.
  • Run behavior handlers: launch, update and exit are now onStart, onUpdate and onStop, matching the naming used by the other behavior types.
  • Editor renames: The Script component is now the Behavior component, with a Class row. Scene Script settings are now Scene Behavior settings, and the project’s Startup script is now its Run behavior. Existing beta.4 projects are migrated when opened.
  • Script API renames: scene.scripts is now scene.behaviors. Entity properties that haven’t been assigned return an Entity with isValid() set to false in both languages. In Luau, these properties previously returned nil, so update any nil checks accordingly.
  • Code moves to Code/: Scripts and script project files now live in a Code/ folder alongside Sources/. This makes it easier to open the code in an external editor without having engine assets mixed in. Existing projects are migrated when opened.
  • Export presets: Presets now distinguish between template and native exports. A template export won’t work for projects that need their own player executable, so switch those presets to native export.
  • MCP tools: script_validate no longer takes className. script_create now takes kind (entity, scene or run) instead of tier, and behavior_add takes class. pie_state and pie_run now use runBehavior and sceneBehavior instead of script and level. The tools are also restricted to reading and writing within the project and folders you’ve allowed.
  • Plugins: Plugins built for beta.4 won’t load. Rebuild your project’s plugins for this release.

Fixes

The full changelog has the complete list. Here are some of the bigger fixes.

  • Editor: Fixed a crash when quitting after opening a picker such as Add Component. Pickers and dialogs now open at the correct size. Entity dragging in the hierarchy works again, and the gizmo, Delete and Duplicate now work on all selected entities.
  • Rendering: Distant trees and grass no longer lose their leaves and fade out. Terrain now renders correctly with MSAA enabled, spot and point lights illuminate their full coverage again, and switching cameras no longer carries the previous camera’s image into the new one.
  • Physics: Character controllers now take part in collisions and queries: raycasts, sweeps and overlaps hit them, dynamic bodies collide with them, and two characters no longer walk through each other. Jointed bodies stay in place, and changing a body’s position or size during play rebuilds it correctly.
  • Stability: Fixed crashes involving blend-tree characters after loading, along with an issue that eventually stopped textured models from rendering.
  • Web: Fixed rendering in Safari on iPhone and iPad, and quick taps are now registered as presses.

What’s new

  • Sequences: The new sequencer lets you build cutscenes using a timeline. Animate multiple entities, play animation clips and sounds, switch cameras, fade the screen and pause at holds until the game is ready to continue. Sequences can be edited in a panel below the scene viewport and played from a script or a Sequence component.
  • Dialogue: Dialogue is now an official plugin. Conversations support choices, flags and custom game commands, with animation, sound, fades and sequences for staging scenes. The editor checks dialogue as you type, and there’s a built-in dialogue box you can use without having to build your own UI.
  • C++ behaviors: Entity, scene and run behaviors can now be implemented in C++ in a project’s own plugin. They work alongside scripted behaviors and use the same events, messages and properties.
  • Android: Games can now be exported as APKs for installation or App Bundles for Google Play. The Android export template is included with this release, alongside the desktop, web and Steam Deck templates. You’ll need the Android SDK and JDK 17 on the machine doing the export.
  • External code editors: Open project code in VS Code or your preferred editor. The Code/ folder includes the declarations needed for code completion and script checking, and script errors in the Console link directly to the offending line.
  • Rebindable controls: Players can change their controls, and their bindings are saved with the game.
  • Other additions: Pointer lock for mouse look, touch drag bindings, interruptible animation transitions, onFixedUpdate for entity behaviors, and Windows crash reports with minidumps.

The documentation has new pages covering sequences, dialogue, plugins and C++ behaviors.

Get it

Download the latest version for your platform, or get 0.1.0-beta.5 on GitHub.

The project manager can download the sample games for this version, and you can also try the release in your browser through the demos.

If you run into any issues, please open a GitHub issue. I’ll take a look.

AssiduousEngine is a game engine in C++23, with its editor, asset pipeline and tools.
