Assiduous Engine 0.1.0-beta.4

14 November 2026

The fourth beta of Assiduous Engine is out.

This release has a lot of fixes, particularly around stability, saving and scripting. I also spent quite a bit of time reworking the scripting API. Math types and entities are now passed around as plain values rather than handles, script errors include their full call stack, and calls between the engine and scripts are considerably cheaper.

There’s also a new graphics quality system. Projects can now define Low, Medium and High settings, making it easier to offer different graphics options for desktop, handheld and mobile hardware.

If you’re upgrading from 0.1.0-beta.3

There are a few changes worth knowing about before opening an existing project.

  • AngelScript scripts: Several types are now value types: Float3, Color, Quaternion, Transform, Guid, Entity, scene facades such as scene.physics, and hit results. Declare them without @ (Entity self;, Color tint), and assign them without @ (self = entity;). Use isValid() to check whether an entity is valid instead of comparing it with null.

    Reading a property now gives you a copy. To change a field, modify the copy and assign it back. For example:

    Color c = light.color;
c.r = 0.5;
light.color = c;

    Assigning directly through the property no longer works. Scripts that still declare these types with @ will fail to compile, with an error explaining the change. Components are unaffected: LightComponent::of(e) still refers to the entity’s actual light component.

  • Luau scripts: Reading a plain property also returns a copy. Changing one of its fields no longer modifies the engine object. Entity lookup is unchanged: scene:find still returns nil if no entity with that name exists.

  • Cooked scripts: Scripts are automatically recooked when opening a project cooked with an older engine version.

  • Quality levels: MSAA and antialiasing settings are now configured per quality level rather than directly on the project or scene. Older projects open with a single Default level, carrying over the previous MSAA count. The antialiasing mode itself isn’t carried over. If a scene previously used TAA or FXAA, the log will tell you which mode it used so you can configure it on the new quality level.

  • Networking: The wire format has changed, so games built with beta.3 cannot connect to games built with beta.4.

  • Building from source: Clang builds on Linux now require LLD. See Documentation/BUILDING.md.

  • Native code: A few API changes: code submitting its own frames should use Queue::SubmitFrame instead of the fenced Submit. MeshComponent no longer contains bone matrices. Content data stream names can no longer contain dots, and Luau’s newproxy has been removed.

Fixes

There’s quite a bit here. The full changelog has everything, but these are some of the more important changes.

  • Saving: Saves now use atomic file replacement. A crash, power loss or full disk should no longer leave an asset, scene, setting or game save partially written. Files that can’t be read are moved aside rather than silently replaced with defaults.
  • Crashes in games: Fixed several cases where destroying an entity or scene from a fixed-step update, event handler or network message could crash the game. Loading scenes and disconnecting from within network handlers are also safe now.
  • Scripting: Script errors now include call stacks. Failed coroutines are reported instead of silently disappearing, and failed engine calls produce errors rather than returning default values. AngelScript compiler warnings are also visible in the editor. Scripts that run forever or allocate without end are now stopped with an error instead of hanging the game or exhausting memory.
  • Script editor: Fixed keyboard input for Return, Backspace, Delete and the arrow keys. Script pages also open immediately instead of taking half a second. AngelScript #include now works, and changes to included files trigger a recook of the scripts that depend on them.
  • Rendering: Fixed several visibility and rendering issues, including lights, sprites, particles and terrain chunks disappearing during busy frames; double-sided materials only casting shadows from one side; animated characters disappearing at the edge of the view; and shared meshes with multiple materials sometimes drawing with the wrong material.
  • Networking: Added checks against malformed and hostile packets. Packet lengths are validated before allocation, unacknowledged and oversized traffic is bounded, and servers now require clients to answer a challenge before creating a peer.
  • File loading: Added safeguards for damaged or deliberately malformed fonts, glTF models, SVG images, XML documents and style sheets. These are now rejected or constrained rather than risking out-of-bounds reads or stack overflows.

What’s new

  • Graphics quality levels: A new Render Quality asset describes a graphics tier, including MSAA, antialiasing, shadow quality, ambient occlusion, reflections, global illumination and bloom, along with limits for shadow distance and environment resolution.

    Projects can define multiple quality levels, and export presets can select a default for each target. That means a phone or Steam Deck doesn’t have to use the same settings as a desktop.

    You can preview levels in the editor, switch between them from scripts using RenderQuality, and the player remembers the selected level. The sample games now include Low, Medium and High presets.

  • Faster scripting: Calls into AngelScript are about a third cheaper. Math operations no longer allocate, and both garbage collectors now do their work incrementally across frames rather than running a full collection pass at once.

  • Code editor: Right-clicking in a script, shader or GUI page now brings up the relevant editing commands, including Toggle Breakpoint.

  • External editors: The new script_declarations MCP tool generates the engine’s script API declarations for external editors such as VS Code. It produces as.predefined for AngelScript and engine.d.luau for Luau.

  • Lower input latency: The editor’s windows now use two swapchain images, reducing the number of frames between input and display.

  • Documentation: Added a scripting cheat sheet with short examples for common tasks in both AngelScript and Luau.

Get it

Download the latest version for your platform, or visit the 0.1.0-beta.4 release on GitHub.

The editor’s project manager downloads the sample games for its version, and you can try this release in the browser through the demos.

If you run into any issues, please open a GitHub issue. I’ll take a look.

AssiduousEngine is a game engine in C++23, with its editor, asset pipeline and tools.
